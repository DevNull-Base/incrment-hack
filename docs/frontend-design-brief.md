# Бриф на внешний вид тестового фронтенда

Текст ниже предназначен для передачи Claude Designer одним сообщением.
Он опирается на реальный контракт API (`openapi.json`, 47 маршрутов), поэтому
макеты можно сразу сверять с тем, что отдаёт бэкенд.

---

## Промт

Спроектируй внешний вид веб-интерфейса для внутренней CRM-системы. Нужны
макеты экранов на одном холсте: сначала десктоп, затем мобильная версия
ключевых экранов. Это тестовый фронтенд для демонстрации на хакатоне —
важнее показать работающую логику интерфейса, чем декоративность.

### Что это за система

CRM для ИТ Школы РТК: контроль взаимодействия с вузами по ИТ-направлениям.
Менеджеры по работе с вузами (КАМ) ведут каждый вуз по процессу из 14 шагов —
от поиска контактного лица до повышения квалификации преподавателей.
Руководители видят работу подчинённых, администраторы управляют правами.

Всего пользователей около 25: ~20 менеджеров, несколько руководителей,
технические специалисты. Это рабочий инструмент на каждый день, а не
витрина: люди проводят в нём часы, и плотность информации здесь важнее
воздуха.

### Роли

| Роль | Кто | Что видит |
|---|---|---|
| Пользователь (КАМ) | Менеджер по вузам | Только свои взаимодействия |
| Руководитель | Начальник менеджеров | Свои и подчинённых, может переназначать ответственных |
| Администратор | Технический специалист | Всё + управление правами, журнал аудита, реестр персональных данных |

Интерфейс один, но состав меню и доступных действий зависит от роли.
Покажи это: на макете администратора видны разделы, которых нет у КАМа.

### Экраны (десктоп)

**1. Вход.** Минимальный экран: название системы, кнопка «Войти через
Keycloak». Пароль в самом приложении не вводится — вход через внешнего
провайдера. Один экран, без изысков.

**2. Реестр взаимодействий — главный экран.** Открывается сразу после входа.
- Панель фильтров: период (от/до), вузы, ИТ-направления, ИТ-продукты,
  ответственные, текущий статус. Фильтров много — продумай, как они не
  съедают половину экрана (сворачиваемая панель, чипы применённых фильтров).
- Таблица. Колонки: вуз, ИТ-направление, ИТ-продукт, текущий статус,
  заинтересованность, ответственный, срок этапа, обновлено. Строки
  с просроченным сроком этапа выделены — но так, чтобы при десятке просрочек
  таблица не превратилась в красное полотно.
- Сверху — счётчики: всего в работе, просрочено, завершено за период.
- Действия: создать взаимодействие, выгрузить отчёт по текущей выборке.

**3. Карточка взаимодействия.** Ключевой экран, на нём менеджер работает
больше всего.
- Шапка: вуз, направление, продукт, ответственный, текущий статус и метка
  заинтересованности с обоснованием — её меняют прямо здесь, одним выбором.
- **Визуализация процесса** — главный элемент. 14 шагов: Поиск контактов →
  Коммуникация → Организация встречи → Обмен документами → (Корректировка
  документов) → Подписание → Передача материалов → Внедрение продукта →
  Обучение преподавателей → Актуализация программы → Ведение занятий →
  Актуализация документации → Повышение квалификации → Сопровождение.
  Плюс боковая ветка «Отказ». Пройденные, текущий и предстоящие шаги
  различимы с одного взгляда. Шагов много — горизонтальная лента из 14
  прямоугольников на десктопе читается плохо, предложи решение. На шаге —
  значки числа заметок и файлов; нажатие на шаг показывает именно их.
- Кнопки доступных переходов (из текущего шага их обычно 1–3). При переходе
  открывается форма: комментарий (для части переходов обязателен) и
  возможность приложить файл.
- Заметки: к текущему этапу, к другому этапу или ко всей заявке;
  закреплённые — первыми. Заметка — не комментарий к переходу: её пишут,
  пока заявка стоит на этапе.
- История переходов: кто, когда, из какого статуса в какой, с комментарием.
  Рядом — полная история заявки: заметки, файлы, оценки, задачи.
- Вложения: png, jpeg, pdf, zip, gzip, rar, doc, docx, xls, xlsx. У каждого
  файла показывается результат антивирусной проверки — «проверен»,
  «не проверялся», «заблокирован».
- Важно: смена статуса **не перезагружает страницу**. Покажи, как выглядит
  обновление на месте, и как приходит уведомление, что карточку изменил
  другой пользователь.

**4. Конструктор отчётов.**
- Выбор колонок из списка (вуз, направление, продукт, статус, ответственный
  и другие), период, фильтры, формат: xlsx, xls, pdf, csv, json.
- Маленький отчёт скачивается сразу. Большой ставится в очередь: появляется
  прогресс выполнения в процентах, по завершении — кнопка скачивания.
  Покажи оба состояния.
- Сохранённые шаблоны отчётов.

**5. Статистика.** Диаграммы по выборке: распределение по статусам,
динамика за период, разрез по направлениям и вузам. Выгрузка диаграмм
в png и pdf. Диаграммы должны честно отражать данные — никаких
трёхмерных эффектов и обрезанных осей.

**6. Импорт из XLS/XLSX.** Мастер из четырёх шагов с индикатором прогресса:
1) загрузка файла; 2) сопоставление колонок файла с полями системы
(«Название ВУЗа» → вуз, «Вендор» → вендор, «ПО» → продукт, «Номер договора»,
«Подписание лицензии», «Срок действия лицензии», «Статус по передаче»,
«ФИО Менеджера», «Ответственные от ВУЗа», «Комментарий»); 3) разрешение
неоднозначностей — система нашла похожие названия вузов и спрашивает,
один это вуз или разные («МГТУ им. Баумана» против полного наименования);
4) предпросмотр: будет создано N, обновлено M, ошибок K — и только потом
применение. Ошибочные строки выгружаются отдельным файлом.

**7. Конструктор процессов.** Редактирование workflow: список статусов
с возможностью переименования, переходы между ними, условия (обязательный
комментарий, обязательное вложение), сроки этапов, роли, которым переход
доступен. Процесс един для всех: публикация правки переводит на неё все
текущие заявки. Перед публикацией — окно сопоставления: для каждого
удаляемого статуса видно, сколько в нём заявок, заметок и файлов, и выбирается,
в какой статус их перенести.

**8. Каталоги.** Вузы, вендоры, ИТ-продукты, ИТ-направления, ИТ-программы.
Таблицы с поиском и формами создания/редактирования. Ничего необычного,
но покажи один экран для единообразия стиля.

**9. Администрирование — пользователи.** Только для администратора.
- Список: имя, адрес, роль, статус (активен/заблокирован), руководитель,
  последний вход.
- Карточка пользователя: смена роли, блокировка, назначение руководителя
  и — самое интересное — ограничение видимости данных по измерениям
  (вузы, направления, продукты, регионы). Покажи, как выглядит настройка
  «этот менеджер видит только эти 5 вузов».
- Опасные действия требуют указания основания — оно попадает в журнал.

**10. Журнал аудита.** Только для администратора.
- Таблица событий: время, кто, действие, объект, IP-адрес, клиент.
- Фильтры: период, пользователь, тип действия.
- Отдельная кнопка «Проверить целостность журнала» с результатом:
  записи связаны хэш-цепочкой, и подмена обнаруживается. Покажи оба
  исхода — «нарушений нет» и «нарушение на записи №…».

**11. Реестр персональных данных.** Только для администратора. Список
контактных лиц с указанием правового основания обработки и срока хранения.
Действия: уточнить данные, прекратить обработку (обезличить). Экран
серьёзный по смыслу — оформи его сдержанно, без игривости; действие
«обезличить» требует подтверждения с указанием основания.

**12. Главный экран менеджера.** Что открывается после входа: заявки,
по которым менеджер работал последние две недели, — карточкой с последним
действием и переходом одним нажатием, ближайшие задачи и сроки этапов
из календаря, непрочитанные уведомления.

**13. Календарь задач.** Месяц и неделя. Два вида элементов: задачи
(на весь день или на время, выполненные — зачёркнуты) и сроки этапов заявок
по нормативу. Просроченное различимо. Форма задачи: что сделать, день,
необязательное время, напоминание, привязка к заявке; у руководителя — выбор
исполнителя из подчинённых. Поручение руководителя исполнитель видит
с пометкой и может только отметить выполненным.

**14. Лента действий.** «Что я менял»: смены статусов, заметки, файлы, оценки,
задачи — по дням, с отбором по виду действия и периоду. Каждая строка ведёт
в карточку заявки.

### Мобильная версия

Три экрана: реестр взаимодействий (карточки вместо таблицы), карточка
взаимодействия с процессом, форма смены статуса. Планшеты и устройства
в горизонтальной ориентации используют десктопную версию — отдельные
макеты для них не нужны.

### Состояния, которые надо показать

Их часто забывают, а на демонстрации спрашивают именно про них:
- загрузка данных (скелетоны, а не крутящийся индикатор на весь экран);
- пустой список — и отдельно «ничего не найдено по фильтрам» с кнопкой
  сброса: это разные ситуации, и подсказки в них разные;
- ошибка. Система возвращает стабильные коды вида `CRM-WFL-0005`. Покажи,
  как выглядит сообщение: человеческий текст + код мелким шрифтом для
  обращения в поддержку;
- конфликт: другой менеджер изменил статус первым;
- превышение лимита обращений с указанием, через сколько секунд повторить;
- длительная операция с прогрессом.

### Требования к оформлению

- **Строгий деловой стиль.** Государственная тематика, корпоративный
  инструмент. Без градиентных заливок во весь экран, без скруглений
  в 24 пикселя, без иллюстраций-маскотов.
- **Палитра:** нейтральная основа (белый, светло-серые поверхности,
  тёмно-серый текст) и один фиолетовый акцент. Не используй реальный
  логотип и фирменный знак Ростелекома — обозначь место под логотип
  нейтральным прямоугольником.
- **Семантические цвета статусов:** в работе, ожидание, успешно завершено,
  просрочено, отказ. Пять различимых состояний, которые не сливаются
  при чёрно-белой печати и различимы при дальтонизме — не полагайся
  только на цвет, добавляй форму или подпись.
- **Метка заинтересованности** — отдельная шкала из четырёх значений:
  высокая, средняя, низкая, не оценено. Она не должна совпадать с цветами
  статусов: «высокий интерес» нельзя спутать с «успешно завершено», а
  «низкий» — с «отказом» или просрочкой, поэтому красный для неё не годится.
  «Не оценено» — контур без заливки: отсутствие оценки не равно низкой оценке.
  Рядом с цветом — подпись или число делений (три, два, одно).
- **Контраст текста к фону** — не ниже 4.5:1. Это прямой критерий оценки.
- **Плотность:** таблица на 25 строк должна помещаться на экране ноутбука
  без прокрутки шапки. Компактно, но не тесно.
- **Логически связанные блоки размещены рядом** — ещё один критерий оценки.
  Фильтры рядом с тем, что фильтруют; действия рядом с объектом действия.
- **Каждый элемент решает задачу.** Если кнопка не нужна в текущем
  состоянии — её нет, а не «выключена».
- Типографика: один гротеск, 3–4 размера, различение весом, а не
  количеством начертаний.

### Чего делать не надо

- Не рисуй настройки профиля, смену пароля и восстановление доступа —
  это делает Keycloak, а не наш интерфейс.
- Не придумывай функции, которых нет: чата и голосовых заметок.
- Не используй тёмную тему как основную — сделай светлую, для рабочего
  инструмента в офисе она уместнее.

### Результат

Один холст с артбордами: 14 десктопных экранов (1440×900) и 3 мобильных
(390×844), подписанные названиями. Перед экранами — небольшой блок
с дизайн-системой: палитра, цвета статусов, типографическая шкала,
основные компоненты (кнопки, поля, таблица, чипы фильтров, карточка
статуса процесса).
