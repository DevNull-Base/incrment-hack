# Роли и информационная архитектура UI

> Источник истины по ролям: `openapi.json` → `CurrentUserDto.role` = **`USER | MANAGER | ADMIN`**.
> Сервер сам применяет data-scope к выборкам — фронт строит только UX-guard и баннеры.
> Хелперы: `src/shared/lib/roles.ts` (`ROLE_RANK`, `can()`, `isAdmin()`, `ROLE_LABELS`).

## Модель ролей

| Роль | Назначение | Отличия в UI |
|---|---|---|
| **USER** | **КАМ** — менеджер по вузам (~20 чел.) | Операционная работа: заявки, вузы, документы, канбан (B2B/B2C), аналитика; **не** меняет ответственного, **не** правит процесс и системные настройки |
| **MANAGER** | **Руководитель** менеджеров | Свои и командные данные, учебные потоки, авто-уведомления о зависших заявках; **не** правит процесс и настройки уведомлений |
| **ADMIN** | Технический специалист Школы | Всё вышеперечисленное + секция «Администрирование»: пользователи, конструктор флоу, аудит, импорт, интеграции, персоны, настройки |

`dataScope { restricted, ownerCount, universityCount }`: при `restricted=true` показывать баннер «Данные ограничены» и скрывать фильтры, которые сервер всё равно обрежет.

## Guard-стратегия (два уровня)

1. **Route guard** — `RequireAuth` + `RequireRole` (`src/app/guards/`): при отказе — редирект на `/`.
2. **Conditional menu** — `visibleSections(role)` / `visiblePages(role)` из `src/app/nav-config.tsx`.

Скрытие пунктов ≠ безопасность: сервер режет scope. Guard — только UX.

## Матрица роль × страница

R = read, W = write, «—» = запрещено (guard → редирект).

| Страница | Route | USER | MANAGER | ADMIN |
|---|---|---|---|---|
| Дашборд (разный контент) | `/` | R | R | R |
| Взаимодействия (канбан B2B/B2C) | `/interactions` | R+W | R+W | R+W |
| Карточка взаимодействия | `/interactions/:id` | R | R+W | R+W |
| Календарь, Уведомления | `/calendar`, `/notifications` | R+W (read) | R+W | R+W |
| Вузы, Программы, Продукты, Документы | `/…` | R | R | R+W |
| Заявки, Workflow, Аналитика | `/…` | R | R | R+W |
| Пользователи, Редактор флоу, Аудит, Импорт, Интеграции, Персоны | `/admin/*`, `/settings/audit` | — | — | R+W |
| Профиль | `/profile` | R (личные) | R | R |
| Настройки системы | `/settings` | — | — | R+W |
| Справка | `/help` | R | R | R |

## Dashboard: по ролям

| Роль | Компонент | Содержимое |
|---|---|---|
| USER (КАМ) | `DashboardManager` («Рабочий стол КАМа») | KPI: заявки в работе, успешные коммуникации, SLA, документы, встречи на неделе; мои недавние взаимодействия; аудит-лента; зависшие задачи; быстрые действия |
| MANAGER (руководитель) | `DashboardLead` | KPI: команда КАМов, в работе, непрочитанные, SLA, успешные; зависшие задачи; загрузка по ответственным; воронка; быстрые действия; аудит-лента |
| ADMIN | `DashboardAdmin` | KPI: пользователи, взаимодействия, вузы, аудит; воронка и «Требует внимания»; quick-links на админ-роуты |

Файлы: `src/pages/DashboardPage.tsx` (роутер по роли) → `src/pages/dashboard/{DashboardManager,DashboardLead,DashboardAdmin}.tsx` + `src/pages/dashboard/blocks.tsx` (общие блоки: KpiCard, StaleTasksBlock, TeamLoadBlock, FunnelBlock, QuickActionsBlock, RecentActionsBlock).

## Ключевые фичи по ролям
- **Авто-уведомления о зависших заявках**: порог 7/14/30 дней (дефолт 14, «1–2 недели» из ТЗ) — заявка без изменений дольше порога → уведомление появляется в ленте автоматически.
- **B2C-workflow**: переключатель сегмента на канбане, отдельная короткая воронка из шаблона B2C.
- **Справка** `/help`: руководства пользователя и администратора внутри продукта.
